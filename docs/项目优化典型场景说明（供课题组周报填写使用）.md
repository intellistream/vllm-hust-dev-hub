# 项目优化典型场景说明

> 供项目组成员选择优化场景与开展针对性测试使用。

**使用说明**：后续项目组成员的优化应尽量落到明确的业务/测试场景中。本文将现有 44 个数据集按典型场景归纳，便于快速选定方向。如果优化的场景与目前所列场景不一致，也可以在周报中填写希望新增的场景，经讨论合理的，可以新增。

44 个数据集的详细信息参见：`vllm-hust-dev-hub/docs/`

## 二、各典型场景简要说明

### 1. 推理/数学

- **场景说明**：面向数学解题、知识推理、多跳问答等任务，适合验证模型在较高认知负载下的质量与服务性能。
- **代表性数据集**：GSM8K、MATH-500、GPQA、BBH、MMLU-PRO、AI2-ARC、AIME-2024、HotpotQA、LongBench-v2
- **重点指标/能力**：质量：Exact Match、数值答案准确率、多选准确率、F1；性能：吞吐、TTFT/TPOT、E2E 时延、成功率。

### 2. 代码

- **场景说明**：面向代码生成、代码执行和测试生成，强调"生成结果能否真正运行并通过测试"。
- **代表性数据集**：HumanEval、MBPP、InstructCoder、LiveCodeBench（Code Generation / Execution / Test Generation）
- **重点指标/能力**：compile rate、execution pass、单测通过率、pass@1 / pass@k，以及服务时延与吞吐。

### 3. 工具调用/Agent

- **场景说明**：面向函数调用、多轮工具使用和 Agent 工作流，关注模型是否能在复杂流程中正确选工具、传参数并保持状态。
- **代表性数据集**：BFCL-V3、BFCL-V4、tau2-bench、ToolBench、EvoScientist、SyFi Coding Trace、HotpotQA-ReAct-100
- **重点指标/能力**：工具触发率、函数名正确率、参数 JSON/Schema 合规率、Agent turn/session 完成率、状态连续性。

### 4. 对话/多轮

- **场景说明**：面向真实聊天请求与多轮会话，既适合作为在线服务基准，也适合模拟不同租户和不同复用程度的请求流。
- **代表性数据集**：ShareGPT-V3、UltraChat-200K、OASST1、WildChat / WildChat-4.8M、PAIO-CHAT-1000、PAIO-REUSE-CONV-5000
- **重点指标/能力**：协议成功率、非空回复率、角色顺序、多轮连续性、完整会话成功率，以及 TTFT/TPOT/E2E。

### 5. 结构化输出

- **场景说明**：面向 JSON、JSON Schema 和固定格式输出，适合验证"格式严格正确"条件下的服务性能与稳定性。
- **代表性数据集**：SchemaStore、JSONSchemaBench、StructEval、PAIO-JSON-500
- **重点指标/能力**：JSON parse rate、Schema conformance、必填字段完整率、字段值正确率、严格 case 成功率。

### 6. 长上下文/KV

- **场景说明**：面向长输入、长会话、Prefix 共享和 KV Cache 复用，是后续系统机制优化的重要场景。
- **代表性数据集**：LongBench、LongBench-v2、InfiniteBench、BFCL 长上下文记录、OASST1 长树、SyFi 长会话、PAIO-LONGTEXT-4000、PAIO-PREFIX-SHARED-5000
- **重点指标/能力**：上下文接收率、静默截断率、HBM 峰值、KV 使用率、Prefix Cache 命中率、驱逐/抢占、长稳故障。

### 7. 多模态

- **场景说明**：面向图像+文本输入的多模态对话和推理。当前若测试模型为纯文本模型，则该场景记为不适用。
- **代表性数据集**：VisionArena
- **重点指标/能力**：视觉任务正确率，以及多模态请求的吞吐、时延和资源占用。

### 8. 固定负载/调度 Trace

- **场景说明**：用于测量基础算力效率或重放真实/突发请求节奏。该类数据不一定承担语义质量评测，但对系统性能和调度评测很重要。
- **代表性数据集**：SONNET、BurstGPT Trace、SyFi Coding Trace
- **重点指标/能力**：A1：MFU、TFLOPS_eff、wall latency、启动/图编译耗时；A4：Jain 公平指数、租户吞吐份额、混跑损失、最差租户 SLO、starvation。

### 9. 企业真实业务场景（派欧云 PAIO）

- **场景说明**：来自合作企业的真实或接近真实业务形态，用于把优化从公开 benchmark 推进到企业请求模式。
- **代表性数据集**：PAIO-CHAT-1000、PAIO-CODE-EVAL-1000、PAIO-JSON-500、PAIO-LONGTEXT-4000、PAIO-LONG-PREFILL-5000、PAIO-PREFIX-SHARED-5000、PAIO-REUSE-CONV-5000、PAIO-SEMANTIC-SIMILAR-5000
- **重点指标/能力**：覆盖聊天、短输出、结构化输出、长 Prefill、Prefix 共享、会话复用、语义相似稳定性等指标；部分数据属于 SUPPLEMENTARY / NON_GATE。

### 10. 生产优化扩展（苏州云能）

- **场景说明**：以真实开源 Issue 为任务源，通过 Agent 实际执行生成编码轨迹，更接近真实软件工程任务。
- **代表性数据集**：SZYN-OPENCODE-SWEBENCH-VERIFIED-500（500 个真实开源 Issue，12 个 Python 项目）
- **重点指标/能力**：真实任务完成情况、Agent 轨迹质量与效率、长会话性能、工具链开销。该数据单列报告，不进入 A1-A4 硬门槛。

## 三、课题验收指标

| 档位 | 核心定位 | 典型数据来源 | 核心指标 |
|---|---|---|---|
| A1 | 有效计算/固定形状/基础开销 | 以合成固定形状为主；SONNET、PAIO Long Prefill / Prefix 可作补充 | MFU、TFLOPS_eff、wall latency、启动/图编译耗时 |
| A2 | 业务功能/质量/在线服务 | 推理、代码、Agent、对话、结构化输出、多模态等大多数业务数据 | 吞吐、TTFT、TPOT、E2E、成功率 + 各领域质量指标 |
| A3 | KV Cache/长上下文/稳定性 | LongBench 系列、InfiniteBench、长会话、PAIO LongText / Prefix | HBM 峰值、KV 使用/驱逐、Prefix 命中、截断率、长稳 |
| A4 | 多租户混合调度 | 复用 A2 请求流按租户角色重放，BurstGPT / SyFi 提供到达节奏 | Jain 公平、租户吞吐份额、混跑损失/时延膨胀、SLO、starvation |

## 四、场景选择建议（仅供参考）

- 如果优化的是模型推理速度、算子、内核或固定形状计算效率：优先选择 **A1** + 推理/代码等一个业务场景做补充验证。
- 如果优化的是在线服务、continuous batching、请求调度或尾时延：优先选择**对话、多轮、代码、推理等 A2 场景**。
- 如果优化的是显存、KV Cache、Prefix Cache、长上下文机制：优先选择 **A3 长上下文/KV 场景**。
- 如果优化的是资源隔离、多租户调度、公平性或突发流量：优先选择 **A4**，并复用 A2 的代表性请求流。
- 如果优化目标强调"真实业务落地"：在公开 benchmark 之外，优先叠加 **PAIO 企业数据或苏州云能生产扩展数据**进行验证。

> **备注**：本文用于场景介绍和方向选择。正式测试时仍应以项目冻结的数据集登记、必测范围、许可和 scorer/oracle 规则为准；PAIO 中部分数据属于补充或 NON_GATE，苏州云能数据为生产优化扩展，不替代 A1-A4 的硬门槛数据。
